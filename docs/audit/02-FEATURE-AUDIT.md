# 02 — Feature inventory and assessment

Baseline `270788d`; 2026-11-11. **53 feature groups** are inventoried below. A group can contain several routes/actions. This is a module-level source and synthetic-test audit, not a claim that every line, language, browser and possible state has been manually exercised.

## Reading the inventory

Roles: O owner, S supervisor, A administrator, U auditor, W worker, P platform operator. Actual route-specific restrictions remain authoritative; a role listed as a reader is not automatically a writer. Expected behavior comes from explicit requirements, current documented contracts and domain invariants. Conflicting requirements are decisions D-01–D-06 in report 03.

Statuses: **L** working with limitations, **B** confirmed broken, **A** architecturally problematic, **U** behavior unclear, **N** not verified. These are overall group assessments, not assertions that all actions in a group fail. No group is labelled unconditionally “working and verified” from source presence alone. Report 08 supplies the execution evidence; the named tests are coverage pointers, not proof of live acceptance.

For each row, the first table identifies purpose/access, expected versus implemented behavior, UI and backend dependencies, and storage. The second table records validation, error/loading/empty states, edges and coverage. Server basenames refer to `server/` and their `server/postgres/` counterpart where present; shared `workspace.mjs` operations are explicitly identified. UI names refer to `src/`. The API is implemented through `server/index.mjs` / `server/postgres/http.mjs`, not generated independently by the UI.

## Assessment limits

No new product feature is recommended by this inventory. The most important cross-feature failures are reproduced in A-03/A-04/A-06, with an independently reproduced inline budget defect A-05. A-01/A-02 are confirmed requirement/implementation mismatches. A-07/A-08/A-09 are integrity/performance/hardening findings with different evidence strength. All-language live acceptance (A-10), real mail/push, physical audio capture, independent accessibility and production infrastructure remain unverified.

The improvement loop does not automatically fix or publish instructions; its deterministic suggestion separates original sentences and requires supervisor review. A-11 concerns its analytics authority, not a demonstrated live generative rewrite.

This inventory should be extended if future changes introduce additional identifiable modules. It must not be read as exhaustive combinatorial coverage of all 53 groups.
